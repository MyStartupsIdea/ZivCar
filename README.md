# avto.uz

Маркетплейс объявлений о продаже автомобилей в Узбекистане: минималистичный интерфейс,
бесплатная публикация, без рекламы и комиссий.

## Возможности

- **Каталог** `/search`: поиск по марке, модели, городу и описанию; фильтры по марке, городу,
  цене, году, пробегу, кузову, топливу, коробке и состоянию; пять сортировок; фильтры в сайдбаре
  на десктопе и в шторке на мобильном.
- **Создание карточки** `/new` в три шага: фотографии → название и цена → описание →
  кнопка «Создать карточку». Фото сжимаются в браузере, первое становится обложкой.
- **Объявление** `/ads/[id]`: галерея, характеристики, счётчик просмотров, телефон по кнопке,
  «Поделиться», похожие объявления, JSON-LD разметка `Vehicle` для поисковиков.
- **Избранное** `/favorites`: сохранение карточек одним нажатием на сердечко.
- **Мои объявления** `/my`: редактирование, снятие с публикации и возврат, удаление.
- SEO: `sitemap.xml`, `robots.txt`, метаданные, семантическая разметка, alt у изображений.

## Стек

Next.js 16 (App Router) + React 19 + TypeScript + Tailwind CSS v4 + lucide-react.
Данные — `localStorage` браузера, бэкенд для работы прототипа не нужен.


## Как устроено

```
src/
├── app/
│   ├── page.tsx                # главная: поиск, марки, свежие объявления, кузова
│   ├── search/page.tsx         # каталог с фильтрами
│   ├── favorites/page.tsx      # избранное
│   ├── new/page.tsx            # создание карточки
│   ├── my/page.tsx             # мои объявления
│   ├── ads/[id]/page.tsx       # объявление
│   ├── ads/[id]/edit/page.tsx  # редактирование
│   ├── sitemap.ts, robots.ts   # SEO
│   └── layout.tsx, globals.css
├── components/
│   ├── Header.tsx, Footer.tsx
│   ├── SearchBar.tsx
│   ├── FilterPanel.tsx         # все фильтры каталога
│   ├── ListingCard.tsx         # карточка + избранное
│   ├── FavoriteButton.tsx
│   ├── ListingForm.tsx         # визард: фото → название → описание
│   └── CarArt.tsx              # SVG-обложка, если нет фото
└── lib/
    ├── listings.ts             # модель, хранилище, фильтры, избранное, хуки
    ├── image.ts                # сжатие фото на клиенте
    ├── format.ts               # цены, пробег, телефоны, даты
    ├── supabase.ts             # клиент Supabase, включён при заданных переменных окружения
    ├── listings-remote.ts      # чтение и запись объявлений в таблицу listings
    └── database.types.ts
```

`src/lib/listings.ts` — единственная точка доступа к данным. При первом открытии в браузер
записываются 18 демо-объявлений, дальше всё живёт в `localStorage`
(`avto.listings.v2`, `avto.favorites.v1`). Этот кэш остаётся источником истины для
интерфейса, а при заданных переменных Supabase он синхронизируется с таблицей `listings`
(см. раздел «Supabase»). SQL-схема (Postgres + Storage + RLS) лежит в
`supabase/migrations/` и описана в `SUPABASE_SETUP.md`.

## Возможности системы

Площадка собрана как несколько связанных модулей, а не одна страница каталога.

| Модуль | Что делает | Где |
| --- | --- | --- |
| Каталог | Поиск по токенам, 10 фильтров, 5 сортировок, состояние в URL | `/search` |
| Карточка | Галерея, характеристики, оценка цены рынка, рассрочка, продавец | `/ads/[id]` |
| Профили | До 4 демо-аккаунтов, создание своего, переключение | `/account`, меню в шапке |
| Сообщения | Переписка покупатель ↔ продавец, непрочитанные, ответы | `/messages`, `/messages/[id]` |
| Сравнение | До 4 машин, подсветка лучшей цены/года/пробега | `/compare` |
| Сохранённые поиски | Подписка на фильтры + новые совпадения после сохранения | `/saved` |
| Отзывы | Рейтинг продавца, оценки 1–5, публичный профиль | `/sellers/[id]` |
| Аналитика | Медианные цены по маркам и городам, структура кузова | `/analytics` |
| Кабинет | Статистика, статусы «активно / снято / продано», действия | `/my` |
| Продавцы | Каталог частных лиц и салонов с рейтингами и счётчиками | `/dealers` |
| Марка | Витрина бренда: медиана, диапазон цен, годы, объявления | `/brands/[brand]` |
| История | Просмотренные автомобили (до 24, очистка) | `/history` |
| Чек-лист | 17 пунктов осмотра с прогрессом и сохранением отметок | `/guides` |

Доменный слой: `src/lib/accounts.ts`, `messages.ts`, `saved-searches.ts`, `compare.ts`,
`reviews.ts`, `analytics.ts`, `credit.ts`, `listings.ts`.

## Публичный деплой

Прототип собран под Cloudflare Workers через OpenNext и опубликован:
**https://site-55ede1455abe4e418b224063f15c7198.freebuff.page** (preview-окружение Sites).

```bash
npx next build

```

Конфиги: `open-next.config.ts` (адаптер, R2-кэш), `wrangler.jsonc` (bindings),
`postcss.config.mjs` (Tailwind v4). Каталоги `.open-next/` и `freebuff-sites-build/`
— сгенерированные артефакты, в git не попадают. Файлы `open-next.config.ts`,
`freebuff.open-next.config.ts` и `freebuff.wrangler.jsonc` тоже генерируются
Freebuff Sites при каждой публикации, поэтому `eslint` их не проверяет.

## Supabase

Проект ZivCar: `wwotwzpslwxluxvcwbvj`, таблица `public.listings`, RLS включён.
Схема зафиксирована в `supabase/migrations/20260101000000_init.sql`, типы — в
`src/lib/database.types.ts`.

Переменные окружения (`.env.local`, в git не попадает) — имена и пример значений есть
в закоммиченном `.env.example`, скопируйте его и подставьте свои:

```bash
cp .env.example .env.local
```

```bash
NEXT_PUBLIC_SUPABASE_URL=https://<project-ref>.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
```

Как это работает: `src/lib/listings-remote.ts` читает и пишет строки таблицы, а
`src/lib/listings.ts` при первом монтировании подтягивает их в локальный кэш
(`avto.listings.v2`) и отправляет в Supabase каждое изменение — создание,
редактирование, снятие с продажи, удаление и счётчик просмотров. Без переменных
окружения приложение работает целиком на localStorage. На пустой базе демо-каталог
заливается автоматически при первом открытии.

Политики RLS сейчас разрешают чтение и запись анонимному ключу — это временная мера
до подключения Supabase Auth; после включения входа их нужно заменить на проверки
`auth.uid()`.

## Ограничения прототипа

- Нет аккаунтов Supabase Auth, модерации и антиспама: профили по-прежнему демонстрационные.
- Запись в Supabase открыта анонимному ключу (демо-политики RLS).
- Каталог рендерится на клиенте: SSR отдаёт только оболочку с состоянием загрузки.
